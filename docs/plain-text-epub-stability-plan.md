普通正文 EPUB 稳定性审查与修复计划，2026-09-09。

本轮交付为审查结论和后续实施计划。审查对象是当前工作区，最近交付版本为 `3.26.09090108`（`29814788`）。本轮没有修改应用代码或测试，没有构建或上传。下文的验证均为拟执行项目，不代表已经通过。

用户报告的两个问题分别是：打开过段评后，退出正文再进入，正文加载不出来；含 `img` 的章节末页在切章时出现透明、虚化，后续页面也可能受影响。需要分别解决生命周期和画面交接问题，并检查两者连续操作时是否相互影响。

源码已确认存在下列缺陷；它们是否完整解释用户设备上的每一次表现，仍须 Android 复现和修复前后对照。

| 问题 | 已确认的源码事实 | 对用户现象的解释及限度 |
| --- | --- | --- |
| 段评关闭后正文计时器被暂停，优先级 P0 | 原始图片 `click` 经 `SourceLoginJsExtensions` 打开默认 GLOBAL 池的弹窗。回池的异步 `about:blank` 完成回调在该池无人使用时调用 `WebView.pauseTimers()`。此 API 暂停进程内所有 WebView 的布局、解析和 JS 计时器；独立正文恢复仅调用实例 `onResume()`。 | 高度吻合“原页面还在，退出后新正文无法就绪”。正文 ready 依赖 `requestAnimationFrame`。这是确定的 API 使用缺陷，尚未在用户设备重现全过程。 |
| 段评关闭后的旧异步回调仍可能写入 WebView，优先级 P1 | 弹窗加载使用 Fragment 生命周期，成功、失败和 JS 异步回调缺少本次 view/租用代次检查；挂起任务的取消还可能被转换为错误 HTML。 | 弱网、快速关闭重开、退出正文时存在旧回调污染风险；暂不能认定它也是本次白屏的主因。 |
| 跨章预览图层没有完整恢复，优先级 P1 | 边界预览将下一章设为可见、alpha=1，并让 overlay 透出 live WebView；当前章仍然可见。取消预览时只归零位移、调整前后顺序，没有把非当前目标恢复为隐藏的候选状态。 | 使用透明阅读表面（如阅读图片背景）时，两章可能叠加。图层状态缺陷确定，用户的“虚化”具体对应哪种动画分支尚待实帧确认。 |
| 图片晚到后的布局与截图状态不一致，优先级 P1 | 图片完成后 JS 触发重排，但原生在动画/交接期间直接丢弃 metrics 更新。`layoutPending` 已被解析却未用于相关就绪判断；动画目标帧可能按仍未更新的原生 revision 再存为有效截图。 | 可能沿用旧页码、旧画面并影响下一次翻页。应一起处理图片变化、动画后同步和缓存失效；尚未证明所有模糊表现都由此产生。 |

实施按以下顺序推进，每一步单独审查差异和相应用例，控制改动范围。

1. **先建立能复现问题的 Android 基线。** 准备离线三章书 A 和纯文字书 B，固定书源 click、正文、末页图片、布局和背景；普通图片、`style=text/TEXT`、软件气泡分别作为样例。通过生产 `executeDirectSourceImageAction` → 默认 `SourceLoginJsExtensions` → 真实 `BottomWebViewDialog`，确保测到实际 GLOBAL 回池路径。原生段落规则的专用段评会话另作对照。记录旧版本的完整事件顺序和画面，为后续每一步修复提供同条件比较。

   只补能串起故障的调试信息：进程/Activity/WebView/会话标识、池 scope 和租用代次、正文 generation/token、load/ready、JS 心跳、章页与字符锚点、图片尺寸变化、layout revision、动画/overlay/live target 状态及截图来源。复用已有诊断，不记录正文、评论内容、书源脚本或带凭据 URL。逐帧采集与性能采样分开，避免采集本身制造卡顿。

2. **修正 WebView 回收和段评生命周期，先消除重入白屏的明确缺陷。** 最小范围为 `WebViewPool`、`BottomWebViewDialog` 和相关 JS 回调生命周期；正文入口仅按验证结果补必要的恢复保护。回收只停止、重置和暂停当前实例；移除“某个池空了就暂停所有 WebView”的行为，明确 acquire/release 与实例 onResume/onPause 配对。GLOBAL、RSS、DISCOVERY 和后台 WebView 共用回收实现，应一起检查。延迟回池不能在新正文恢复之后再暂停其他实例。

   弹窗任务改由 view 生命周期管理，取消异常正常传播；view 销毁时撤销本次任务和回调。正常返回、异常返回和 JS 结果都检查 view/租用/页面代次，旧请求不能写入已回收或复用的实例。保持原始 `click` 行为以及正文的源、书、章校验；Direct 中的段落规则和 `pclick` 继续关闭。

   验收：关闭一个池中 WebView 不影响独立正文的 JS/rAF 心跳；关闭段评、退出重入与跨书均可见、可翻页；快速关开和请求取消没有旧结果回灌。实现不能仅依赖重入时额外调用 resumeTimers，因为旧回池回调可能更晚发生。

3. **统一跨章预览与翻页收尾的图层状态。** 最小范围为 `EpubDirectWebLayer` 和 `EpubDirectPageAnimationOverlay`。分别明确当前正文、候选章、预加载章、动画快照的角色和显示区域；live target 露出时，阅读背景之上只合成该区域应显示的章节内容。保留图片背景的正常显示，不用固定白底掩盖叠层。

   成功、取消、反向拖动、目标加载失败、超时、切后台和销毁都按最终角色恢复 visibility、alpha、位移、裁剪、层级及临时 layer 状态，非当前预览恢复到既定候选状态。收尾必须可重复调用，过期动画回调不能修改新一轮页面；完成交接后再允许把画面作为稳定截图缓存。

   验收：预览进行中不会透出另一章的非预期文字；取消后只恢复正确的当前页；成功后当前章及下一页无旧章叠影，overlay 和临时变换均已释放。纯色背景和图片背景都覆盖。

4. **将图片重排、动画后同步和旧截图失效作为一次完整修复。** 最小范围为 `direct-runtime.js`、`EpubDirectWebLayer` 及确有需要的帧元数据/缓存键。动画期间合并记录待同步状态，按当前会话和目标章过滤；动画完成或取消后重新读取当前页面 metrics，校准页码、页数和字符锚点，再处理下一次排队翻页及截图。旧 generation 的更新不能提交到新章。

   激活与截图判定同时考虑目标页内容是否可见、当前可见页是否仍在重排，以及目标定位对应的布局版本。图片内容或尺寸变化时，需要使受影响的已提交截图、相邻页帧和正在采集的旧结果失效；动画目标帧只有与最新文档、资源状态、布局和视口相容时才可回存。不同 WebView 的局部 revision 不能无条件当成可互比的全局版本。

   保留慢图异步加载和占位，按可见页稳定程度决定交接，不等待全章图片完成。资源失败或暂缺动画材料时，保留已提交的有效正文，使用有时限的重试或直接切换到已就绪正文，防止无限加载。重排按帧合并、截图刷新合并，避免每张图完成都触发整章重载或反复截图。

   验收：图片恰好在翻页时加载完成、失败或命中缓存，都能得到正确的新页状态；下一页不会再次使用旧图或错位截图；目录定位、正反向跨章和字符进度保持一致，慢图不阻塞文字阅读。

5. **完成完整操作链的复核，再形成发布候选。** 先跑有行为断言的相关回归、构建和既有兼容检查，再做 Android 同条件对照；交叉审查重点是未覆盖的取消、失败和过期回调分支。保留现有 JVM/浏览器用例用于局部回归，新增验证应执行实际 Android 生命周期和窗口显示链。待实施时，发布包还应检查签名、版本、运行时资产和已有 ICU/类初始化回归；本轮不执行打包或 R2 上传。

Android 验收矩阵如下。当前未确认用户使用的翻页模式，以及失败后重启进程能否恢复；先覆盖各支持模式，收到信息后优先按用户配置复现。

| 验收项 | 操作及边界 | 通过条件 |
| --- | --- | --- |
| 段评后同进程重入 | 不开段评作为基线；开段评→关闭→书架→重入 A，连续 30 轮；再覆盖 A→B→A。轮间不杀进程。 | 每次正文可见且可操作，锚点正确，另一书正常，心跳不断，无旧 Activity 结果提交。 |
| 段评异常时序 | 加载中关闭、弱网/失败、快速开关、段评未关退出正文、立即退出与延迟退出、后台恢复、Activity 重建；补 GLOBAL/RSS/DISCOVERY 和后台 WebView 回收。 | 回收仅影响自身，旧回调失效，正文和后续段评继续工作；内存/存活 WebView 不持续累积。 |
| 含图末页切章 | 无图对照；普通 img、text/TEXT、气泡；图片已完成、跨切章晚到、失败；预加载命中和未命中。前进、后退、半拖取消、反向拖、快速连翻均覆盖。 | 前章末页、交接帧、后章前两页没有非预期透字、持续变淡、旧图残留或空白；当前书/章/字符位置一致。 |
| 背景和动画 | 用户实际模式优先；仿真、覆盖/滑动、无动画及滚动分别验证，覆盖纯色与阅读图片背景。 | 图层显示与所选动画一致，完成和取消后的状态一致；图片背景显示正常。 |
| 组合与兼容 | 开段评后立即切含图章节，再退回书架重入；普通正文原生/Direct 切换，本地 EPUB 作对照；目录跳转和字体重排后检查进度。 | 两处修复共同工作；原始 click 可用，Direct 不执行段落规则；独立排版设置、目录及进度保持原语义。 |

设备记录包含 Android 版本、System WebView 包及版本、布局/背景/翻页设置。使用系统录屏或窗口 PixelCopy 检查实际合成画面，并记录图层及祖先的 alpha/visibility/translation；`View.draw(Canvas)` 或 DOM ready 不足以证明没有叠影。窗口截图通常已经合成为不透明，像素 alpha=255 也不能证明文字没有变淡，应比对固定文字区域的亮度、对比度和内容。

画面收尾判据从“动画完成、最后一次影响可见页的重排完成且交接稳定”开始计时：随后两个实际显示帧内应恢复正常正文层，后续两页保持正常。慢图可继续保留占位，晚到时单独验证重排与锚点。记录首个可见正文耗时、切章稳定耗时的 p50/p95、卡顿与退出后的 WebView/内存趋势，并与同设备同数据的基线比较；不能用桌面帧率推断设备性能。

当前 `adb devices -l` 无设备，SDK 也没有可启动的模拟器镜像或 ART 环境。因此，本轮能确认源码/API 使用缺陷和测试缺口，不能宣布两个问题已在 Android 复现或修复。实施阶段需补可用 Android 环境；上述关键链路未通过前，不把构建成功或桌面回归成功当作稳定性验收完成。
