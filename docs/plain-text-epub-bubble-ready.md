# 普通正文 EPUB 排版：加载阶段准备本地气泡

本轮处理软件气泡在正文进入页面后才生成、补入并改变布局，以及从气泡上开始滑动时翻页被拦截的问题。仅调整普通正文的 EPUB 排版链路。

## 实现

- 章节正文完成原文替换净化后，先识别无需网络或书源加载脚本就能确定的气泡。包括显式 `dp:`、`bubble://paragraph`，以及当前软件气泡设置允许转换的静态图片来源。
- 复用 `TextReaderImageLoader.renderBubble`，仍经现有 `ParagraphBubbleRenderer` 处理气泡包、字体、主题和尺寸，再输出 PNG。没有另建一套 SVG 模板解释器。
- 将生成的小图片和 `isBubble`、`scale` 一起写入首份 HTML。它们不再注册到异步图片队列，而是经过现有普通图片的加载、解码及布局等待。
- 保留原图 ID、原始 source 和 click 动作映射。图片仍不贡献朗读字符，正文、目录与章节定位算法保持现有逻辑。沿用透明点击高亮和原文替换净化。
- 普通远程图和需要加载脚本的图片继续异步，不能因排在前面而占住本地气泡的准备机会。
- 可点击气泡的链接只保留点按动作。旧 runtime 会在触摸开始时把所有 `a[href]` 都当作独占手势，native 收到后便取消整次翻页；现在普通正文图片和生成的动作链接允许原生滑动接管。点按仍由原有命中判断处理，滑动时的 CANCEL 仍会清理图片长按定时器。原 EPUB 链接、放大层、输入控件及可滚动部件继续保持各自的触摸行为。
- 图片及生成链接的空白区域共用经过图片 ID 核对的动作目标识别，避免点击边缘时将内部占位 `href` 误交给外链处理。

## 开销与失败处理

预生成只使用本章局部缓存；相同 canonical 气泡只生成一次，失败也只尝试一次。没有新增跨书籍、跨字体或跨主题的全局图片缓存。

默认预算：最多 64 种气泡，单张原始图片不超过 64 KiB，按每次 HTML 引用累计不超过 512 KiB 图片数据及 1 Mi 字符 data URI。整批采用 1500 ms 的协作式时间预算。原生 SVG 解析若未响应线程中断，只能在返回后丢弃超时结果，因此该数值不是任意模板的绝对耗时保证。

准备失败、超预算或必须执行加载脚本的图片沿用已有异步路径，不使整章失败。外部取消仍向上传递；在准备前后核对书籍 session 和章节状态，避免切书后的迟到结果进入当前正文。

已有首次资源准备还有 3200 ms 兜底。因此此变更减少正常本地气泡的后补与重排，不承诺在极端超时、失败或异步脚本场景下绝不后补。

## 验证范围

- JVM：静态来源识别、脚本排除、重复复用、失败与预算回退、超时及外部取消、资源导出限额；首份 HTML 的尺寸、点击 token 和字符偏移。
- 浏览器：使用本轮 JVM 调用生产准备及文档构建 API 导出的页面，检查首次 stable 时图片已解码、三档缩放已生效、前置慢图仍 pending 时正文可以就绪、翻页及滚动后几何尺寸稳定。
- 密集气泡与手势：增加 243 个气泡的正文页面；用触摸事件验证图片及链接区域的拖动不再发送独占触摸锁，单点、双击、长按和真实控件保持原行为。以旧 runtime 运行相同触摸作为反例，并用本轮 runtime 重跑既有图片异步、布局稳定与原 EPUB 兼容检查。
- 内测包：延续现有 JVM、Lint、DEX 链接与 ICU 检查；冻结本轮输入、测试报告、浏览器材料和 APK 校验值后，上传固定 APK 与 `latest.json`，逐对象回读核验。

浏览器材料以受控 PNG 替代 Android 原生 SVG 栅格化，并模拟 native bridge，不能替代实际 WebView、气泡包资源、字体与设备画面的验收。本轮未连接 Android 设备，发布渠道仍标注内测候选及未实机验收。实际检查结果以本轮 `output/text-reader-bubble-ready-*` 报告为准。

原生层仍会在重排期间等候有效页码测量，防止使用旧画面导致透明或错误翻页。预生成能减少气泡引起的此类等待，但不会强行绕过门禁；大量需执行书源加载脚本的图片仍可能陆续触发重排。当前没有证据证明有限图片完成后存在必然无法恢复的死锁，因此本轮不改动该恢复链路。
